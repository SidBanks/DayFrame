## 1. Selected decision and guarantee boundary

Carry a **qualified source snapshot** through the canonical Review projection and shared eligibility, and bind fresh publication to an owner-issued, synchronously recheckable source witness. Required Proposal authority is whole-authority qualified. Missing/protected/actively unsettled acceptance evidence cannot supply a healthy empty accepted-liability list. The final qualification/source check occurs in the existing physical admission callback, immediately before native transaction creation.

Use existing lifecycle identities, quiescence, current snapshots and synchronous source access. Add only runtime observation revisions/snapshot adapters where existing access cannot distinguish a state transition. Do not add a cross-owner lock, queue, transaction, polling loop or persisted ledger. Publication keeps its FIFO queue and executing-head lease; Proposal and realization keep their separate nonqueued leases and original-lifetime handoff.

This guarantee covers one registered participating store composition in one live JavaScript realm. Arbitrary raw writes, independent active stores/tabs/devices and comprehensive writer safety are excluded. Additional source owners below participate only through the facts publication consumes; this does not certify or redesign their writers.

Three acceptance uncertainty variants currently return protected Proposal evidence but permit publication through a fresh Review fingerprint. Real adapter diagnostics reproduce that behavior; **future repaired behavior is zero newly created HistoricalPlan transactions in those cases**. Current successful defect-confirming tests are not repaired evidence.

## 3. Concrete runtime evidence types

The following are **proposed runtime types**, not claims about current enums. Existing durable records and owner command unions remain unchanged except the explicitly proposed publication runtime additions in §7. Owner adapters retain typed original ingress reasons as `ownerReason`; no raw attempted authority is exposed.

```ts
type PublicationSource =
  | "proposal"
  | "realization"
  | "activeSetup"
  | "planDecision"
  | "composition"
  | "goal"
  | "sleepFoundation"
  | "historicalPlan";
type QualificationReason =
  | "initializing"
  | "readUnavailable"
  | "protected"
  | "writeInProgress"
  | "commitUnconfirmed"
  | "verificationFailed"
  | "coverageIncomplete"
  | "pendingDurability"
  | "qualificationUnavailable";
type Coverage =
  | { status: "complete"; basis: "wholeAuthority" | "canonicalRange" }
  | { status: "partial" | "unknown"; basis: "wholeAuthority" };
type PublicationSourceIssue = Readonly<{
  source: PublicationSource;
  reason: QualificationReason;
  ownerReason?: string; // copied actual owner reason; not parsed for policy
  coverage: Coverage;
}>;
type SourceQualification =
  | {
      status: "qualified";
      coverage: Extract<Coverage, { status: "complete" }>;
      basis: "verifiedCommitted" | "qualifiedPriorCommit" | "currentRuntime";
      lastWrite:
        | "none"
        | "verified"
        | "knownNotWritten"
        | "runtimeAcceptedPending";
    }
  | { status: "unqualified"; issue: PublicationSourceIssue };
type QualifiedSource<T> = Readonly<{
  source: PublicationSource;
  records: { status: "readable"; value: T } | { status: "unavailable" };
  qualification: SourceQualification;
  // Private owner-issued identity: never serialized, supplied or forged by UI.
  witness: object;
}>;
type PublicationSourceFailure = Readonly<{
  reason: "publicationSourceUnqualified";
  sourceIssues: readonly [PublicationSourceIssue, ...PublicationSourceIssue[]];
}>;
type PublicationSourceCheck =
  | { status: "current" }
  | { status: "rejected"; reason: "contextReplaced" | "sourceChanged" }
  | ({ status: "rejected" } & PublicationSourceFailure);
```

Owners supply a synchronous `capture...Evidence()` combining settled records, qualification and a recognized witness in one non-reentrant call. Composition root adapts actual owners once; UI never imports raw-owner policy. A private `checkPublicationSources(witness): PublicationSourceCheck` captures current qualification and compares identity/content without async derivation. No boolean false erases a source-specific denial.

Replace the live derived Review contract with **PlanningReviewReadModelV2**, with `version: 2`, existing independent fields, mandatory `sourceQualification`, `queryState: "current" | "sourceChanged" | "contextReplaced"`, and `publicationWitness: {status:"publishable"} | {status:"blocked"}`. The owner-recognized witness is held privately (WeakMap keyed by original result or equivalent non-enumerable shell receipt); serialized JSON is inspection data, not a live admission token. The mandatory `sourceQualification` is a readonly record keyed by PublicationSource for the dependency set in §2 (no omitted required key); each value is SourceQualification. `queryState` is current only when all captured witnesses survive the query, even when current qualification itself is blocked. Existing sourceFingerprint stays a string, defined in §6. All in-repository live callers migrate together; supported durable V1 records/readers do not change.

Replace naked acceptedLiabilities/scheduledReality/proposals consumption with qualified families `{ records, coverage, availability }`; retain their existing record element shapes. Availability is `available | unavailable | protected | unsettled`; it is derived by the single source mapping: qualified → available; unqualified protected/commitUnconfirmed/verificationFailed → protected; writeInProgress → unsettled; other unqualified reasons → unavailable. Readable records may accompany any family, with coverage partial/unknown. Empty rows only support a zero total when relevant qualification is complete. An unknown cross-family subtraction has no authoritative liability total; known prior items may be inspected with explicit partial coverage.

## 5. Range and healthy-control rules

Proposal and realization qualification are whole-authority. No per-range completeness certificate exists today. Protected absence, cached dates, filtered offers, selected Goal, attempted claims or stale earlier records cannot establish irrelevance. A wholly qualified source can be filtered using existing canonical interval/day rules: known out-of-range accepted claims do not block an otherwise eligible period. A protected owner containing only readable out-of-range records still blocks, because missing coverage has no trusted range exclusion.

Keep Review Scope, prospective Publication Range, Proposal Horizon, Planning Data Horizon, generated Preview span, Calendar and local filters separate. Publication creates its own exact Review scope from Publication Range and validates the supported canonical range. Inclusive human labels do not alter half-open command endpoints. Sleep's existing guard/neighborhood/Preview span can require evidence outside the visible period.

Qualified empty authority, a known abort with no prior acceptance, healthy pending offers and healthy no-prior-history all remain eligible subject to other existing blockers. Pending offers never require decision before Build. Existing accepted-but-unrealized liabilities still block; complete realized facts exclude their actual corresponding liabilities. Incomplete/legacy Accepted Allocation V1 remains inspectable and not upgraded or newly realizable. Keep its current claim-based liability projection; unknown _owner coverage_ is distinct from the known incompleteness of a supported record. Do not fabricate missing claims or a new legacy blocker.

Independent Goal/G2/Activity/history/Actual/Progress inspection retains its own availability rules. Publication qualification neither hides otherwise lawful independent evidence nor supplies missing G2 evidence.

## 6. Query coherence, witnesses and fingerprints

Capture query origin (store identity/epoch/generations) synchronously before lazy dispatch. After lazy loading, capture all synchronous required source snapshots together in one non-reentrant turn, before awaited history reads. Include saved setup, Preview, Goals, Proposal/realization records and qualifications, corrections, Composition and transitive Sleep inputs. Copy/freeze the exact data used for projection and materialization. Capture source observation stamps and HistoricalPlan read revision; never read records from one capture and status from another.

Await existing history range and needed seam/collection reads using that origin. After each await and after synchronous derivation, check origin and the captured source witnesses. A decisive current unqualified source produces publicationSourceUnqualified with its current issue. A healthy changed content/observation stamp produces sourceChanged; replacement produces contextReplaced. Return a blocked, explicitly stale query, no publishable witness, retaining separately labelled readable evidence. Do not combine old rows under a new scope/qualification heading. A later explicit query may succeed; there is **no internal retry-until-stable loop**.

Required observation identity changes synchronously on authority replacement/adoption, qualification/protection-instance change, and acceptance/realization lease acquire/release. Existing owner generation/desired version/active identity plus immutable snapshot identity are reused. A small monotonically advanced runtime observation revision closes remaining same-bytes/ABA and status-only gaps; it carries no command exclusion or durable meaning. The persistent lazy shell owns these observation hooks across install/module load. Listeners must be retained before loading, with synchronous invalidation before delayed UI notifications. Ordinary unrelated Proposal history may cause a query to retry explicitly for coherence but does not change immutable acceptance or operation receipt currentness.

Historical range and seam evidence must come from **one owner-captured immutable collection view**: synchronously freeze the settled metadata/batch identities, accepted pending batch identities and history qualification, read exactly those physical batches through existing validators, and derive the range using the existing effective-day projector from that same collection. Do not combine an unrestricted later indexed range with an earlier metadata export. This read-only adapter is part of the selected handoff; the current query’s two independent reads are not a sufficient coherent view. Ordinary appended batches outside the capture are not silently mixed into it; replacement/protection or a changed observation during the read makes the result stale. An executing healthy FIFO predecessor need not be declared corrupt/busy merely to inspect its prior settled history view; the queue head still revalidates current complete history before publication.
