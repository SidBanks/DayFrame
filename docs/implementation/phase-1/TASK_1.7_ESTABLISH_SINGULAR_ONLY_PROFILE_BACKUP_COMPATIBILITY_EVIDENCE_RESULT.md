## Architectural determination

Both expected compatibility paths are supported by current production code.

- A saved profile containing singular `shiftCycle` with `shiftCycles` absent is
  accepted, normalized, loaded, and exposed as plural runtime authority.
- A Version 1 backup containing singular `shiftCycle` with `shiftCycles` absent is
  accepted by JSON parsing/validation, normalized, imported, and exposed as plural
  runtime authority.

No production modification was needed. Direct executable evidence now protects both
readers from accidental removal.

## Investigation completed

### Profile path

```text
literal profiles-storage V1 payload
    data.shiftCycle present
    data.shiftCycles absent
        -> loadPersistedProfiles
        -> validateDayFrameProfilesStorage
        -> normalizeAuthoredSetup singular fallback
        -> createDayFrameSavedProfile / clone
        -> store.loadProfile
        -> createInitialDayFrameState
        -> runtime shiftCycles authority
```

If both fields are present, the profile normalizer checks for an array-valued
`shiftCycles` first. Existing repeating-sequence profile coverage supplies a plural
cycle that differs from the singular value inherited by its fixture and observes
the plural result, establishing plural precedence.

### V1 backup path

```text
literal backup JSON V1 payload
    data.shiftCycle present
    data.shiftCycles absent
        -> parseDayFrameBackupJson
        -> validateDayFrameBackup
        -> normalizeAuthoredShiftCycles singular fallback
        -> clone normalized authored data
        -> store.importBackup
        -> createInitialDayFrameState
        -> runtime shiftCycles authority
```

The backup normalizer likewise checks array-valued `shiftCycles` first, so plural
data has precedence when both representations exist.

## Exact legacy fixtures established

The shared test fixture is a literal authored-data object containing:

- schedule preferences and Preview range;
- current shift definitions;
- one singular `shiftCycle` lacking modern `mode`, `sequenceAnchorDate`, and
  `sequence` fields;
- block templates, recurrences, and manual events;
- **no `shiftCycles` property**.

Each test explicitly asserts the plural property is absent before invoking the
supported boundary. The fixture is not generated by profile or backup serializers,
so future writer modernization cannot silently modernize this compatibility input.

## Observed normalization

Both paths produce one plural cycle with the legacy identity and data plus current
normalization defaults:

- `mode: "manualSegments"`;
- `sequenceAnchorDate` equal to `startsOnDate`;
- `sequence: []`.

After profile load or backup import, `state.shiftCycles` contains this normalized
cycle and the existing runtime `state.shiftCycle` compatibility view equals its
first entry. The ensuing local authored write remains plural-only under Task 1.6.

## Current writer observation

Store-created profiles and store-exported backups extract authored data with plural
cycles but no singular source. The shared clone helper currently materializes the
optional singular property as `null`. Tests now explicitly record:

```text

shiftCycle: null
```

Task 1.7 does not change that output.
