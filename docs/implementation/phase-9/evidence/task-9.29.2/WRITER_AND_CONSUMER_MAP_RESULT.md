# Final writer, installer and consumer map — RESULT

Current implementation, not the older implicit-generation model. Source hashes and task-relative changed-file accounting accompany this map. Paths are relative to `code/src/`.

| Route                      | Final owner/boundary and effect                                                                                                                                                                                                                                                                                                                                   |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Public dispatch            | `state/dayFrameStore.publishScheduleRange` captures the owner origin and clones requested input before lazy import; checks admission before/after import, propagates original origin, and returns a completion receipt even for conservative unexpected failure. The generic mutation proxy no longer converts active-publication dispatch into an untyped throw. |
| Review/materialization     | `state/schedulePublication` clones the request, checks lifetime after the asynchronous canonical query and before materialization; preserves reviewed fingerprint, capacity witness, range and caller time. No auto-refresh or rematerialized retry.                                                                                                              |
| Atomic publication         | `state/historicalPlanSurface.publishAtomically` clones candidate intent, joins the existing FIFO owner queue, acquires the executing lease before async owner work, and supplies result recording inside settlement. Ordinary healthy later submissions remain queueable.                                                                                         |
| Retained legacy publish    | Factory `publish(batch)` uses the same queue/lease and retains accepted exact pending batches on known failure. It remains supported; no production DayFrameStore direct legacy publish method was added.                                                                                                                                                         |
| Deduplication              | Existing semantic day fingerprints and ordering remain. Lifetime/source checked before no-op; effective pending-only match returns `identicalPending`, not durable success. Existing-ID persistence verification preserves exact batch identity/time and complete frozen days.                                                                                    |
| Physical writer            | Owner `persistBatch` supplies post-open synchronous admit checking attempt-open flag, exact active origin, generation/epoch, admission/protection and source. Atomic metadata/day mutation remains in existing stores.                                                                                                                                            |
| Adapter                    | `infrastructure/storage/indexedDbCollectionStorage.mutate` retains optional admission and adds optional internal receipt observer. Receipt is registered after native terminal handlers, before requests; enqueue failure aborts and awaits terminal. `onerror` alone does not terminate it.                                                                      |
| Lost acknowledgment        | Owner closes attempt admission on error, awaits any registered native terminal, and retains protection. Native terminal observation also schedules a MessageChannel task checkpoint for absent outward acknowledgment: normal promise delivery drains first; missing acknowledgment becomes uncertain. No timer declares a live transaction cancelled.            |
| Verification/adoption      | Lease includes complete verification, metadata/pending disposition, protection capture, last-result recording and synchronous notifications. Only then does it release. Settled protection and live-work busy are separate.                                                                                                                                       |
| Exact retry                | Public store/factory retry captures current origin, joins the same queue and writes original accepted batches. Uncertain/possibly committed attempts leave ordinary retryable pending state. No new identity/time or setup-based reconstruction.                                                                                                                  |
| Initialization             | Cached by origin lifetime, checks after open/metadata await; automatic flush can only follow completed current initialization and enters the queue. Replacement/abort/epoch invalidation suppresses displaced automatic flush.                                                                                                                                    |
| Reads/install effects      | Day/range/evidence/export continuations check their captured lifetime; stale reads explicitly return unavailable/contextReplaced. Runtime install increments generation, excludes tokens from snapshots, and tags deferred notifications.                                                                                                                         |
| Protection/recheck/export  | Protection evidence continuation requires both matching origin and exact loading instance. Recheck detects displaced source and never unlocks readiness; protected export is read-only. No new recovery UI.                                                                                                                                                       |
| Direct clear/abandonment   | Attached direct clear enters shared replacement; standalone clear uses local exclusion. Existing protected abandonment temporarily admits only its own established private route, rechecks exact raw source under exclusion, and never skips physical quiescence. Private clear requires capability plus matching active epoch.                                   |
| Shared begin               | `state/dayFrameAuthorityTransaction` checks combined Structure/HistoricalPlan quiescence and structured HistoricalPlan protection before snapshot work; activates/advances epoch before snapshot callbacks. Failed snapshot keeps lifetime invalidation.                                                                                                          |
| Restore/full clear         | `dayFrameStore`, `dayFrameRestoreComposition`, existing `restoreCoordinator`: full clear uses private HistoricalPlan clear; ordinary protected begin maps to protectedCurrentState; busy maps to existing restoreBusy or clear admission error. Composition forwards optional receipt observation while preserving its private epoch callback.                    |
| Rollback/startup           | Existing journal/staging/source checks, combined IndexedDB replacement, localStorage reread/anti-resurrection, exact recovery and runtime translation/install/finalization remain. Recovery never bypasses physical quiescence. Existing protected capture limitations are not broadened into new repair authority.                                               |
| Public result/current slot | `publicationReceipt` is a small runtime envelope helper, not a state owner. Receipt is non-enumerable and never serialized. Store records current settlement inside lease and hides a displaced last result.                                                                                                                                                      |
| Review consumer            | `ui/ScheduleReviewPanel` explicitly maps contextReplaced, publicationBusy and pendingPublication; preserves certainty copy; stale receipt cannot install success or refresh current Review.                                                                                                                                                                       |
| Utilities/context          | `ui/DayFrameApp` explains busy/protected/unknown clear and restore results, clears busy state in finally, resets Goal editing only after accepted clear, preserves drafts on rejection, closes rejected clear confirmation and restores Clear button focus. Subsequent import feedback remains visible.                                                           |
| Current-surface targets    | Scoped `dayFrameUi.css` rules bring affected Review primary controls to at least 44px. No Review navigation/layout convergence, hiding of overflow, or third destination.                                                                                                                                                                                         |

The guarantee remains one registered store/owner in one live realm with participating adapters. Raw external database writers, other active stores/tabs/devices and preserved Dogfood state are outside the exercised boundary. No schema/version/backup/staging/journal representation changed; no capability or reader was retired.
